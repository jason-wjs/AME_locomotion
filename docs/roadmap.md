# AME 研究路线图

更新日期：2026-10-16。本文记录已确定的方向和阶段边界；完成状态以代码、配置和实验记录为准。

## 项目目标

长期目标是面向 humanoid robot 的地形感知运动控制训练与研究。近期继续使用 AME
定位和名称，以 G1 为验证对象，逐步覆盖连续地形、稀疏落脚和两者之间的过渡。

下一阶段的行为目标是：同一个行走策略通过平地、坡面、楼梯、踏脚石及其连接区域；
普通地形动作自然，困难地形允许必要的动作调整，同时降低达到相近效果所需的训练
时间和峰值显存。这里的“跨地形”有明确的测试范围，不表示已经解决任意地形。

## 第一阶段交付

当前 `upgrade/mjlab-1.6` 保留社区 `g1` 默认算法，完成 mjlab 1.6.0 兼容升级。
稳定源码 `99b8aa45435832af90f2f280a8f9ce757bee2409` 保留在
`stable/ame1-community`。当前正式训练基于
`a95d88d2a05d4eaca713945da4802a8b8d40d3d6`。

本阶段仍需完成正式训练结果检查、checkpoint 和演示整理，与 README、docs 及维护者
负责的其他文字一起交付到升级 PR。保留第三方原作与署名，不统一改写第三方文档。
训练耗时记录到小时级即可，不以重新建设严格评估框架为交付前提。

公开权重目录使用 `checkpoints/`，提供训练配置、代码版本、加载方法和演示。
合入前检查权重能够加载、运行和恢复；训练退出成功不等于效果验收通过。
根据实际结果回复 Issue #1，说明迟复、训练条件、耗时和可用成果。
本阶段不切换默认算法，也不发布新版本。

## 第二阶段实施顺序

| 步骤 | 实施内容 | 进入下一步的依据 |
| --- | --- | --- |
| 1 AME-2 teacher 基线 | 迁移官方地图编码、目标任务、动作与观测约定、critic 和学习配方；记录 mjlab 适配差异 | 在真实环境中完成 rollout、PPO 更新、保存及恢复；关键语义与官方代码逐项核对 |
| 2 感知效率 | 先分析采样、网络更新、地图构建和缓存的时间与显存，再比较完整地图、固定裁剪、学习式裁剪 | 相同任务与预算下，明确各方案的通过能力、端到端耗时及显存差异 |
| 3 任务与支撑约束 | 检查目标采样、指令、课程、边缘惩罚及足部支撑质量 | 能解释典型失败，避免重复惩罚、不可达目标和停滞获奖 |
| 4 自然行走 | 先检查 PD、动作缩放、控制频率和奖励，再接入经过检查的 AMP 动作数据 | 同速回放更自然，且没有明显损失困难地形通过能力 |
| 5 组合验证 | 只组合已经证明有效的改进，训练混合地形策略 | 同一策略能够处理代表性地形及连接段，发布配置、权重、视频和已知失败 |

这些步骤属于同一研究阶段，按可审查的小改动推进。实现与实验不一次性混入全部设计。
性能分析、数据检查和接口准备可以提前进行；正式对照仍保持明确的依赖与顺序。

### AME-2 基线的含义

官方参照锁定 `leggedrobotics/ame2_minimal` 的
`8beb9a688d67882828019583f7d5a78e3517f233`。迁移对象首先是已发布的 teacher，
参照该版本代码，不把其所有新增选项都当成论文原始配置。

当前社区任务是速度跟踪，官方 teacher 是目标到达任务。需要明确目标、观测、
动作顺序、坐标系、奖励分量、课程、随机化及优化器的差异；仅替换网络不能称为
完整 AME-2 迁移。mjlab 的物理与任务适配必须记录，不能宣称与 IsaacLab 数值等价。

官方参照保留 MoE critic。我们的改进版本默认采用单一 actor；不预设 MoE actor、
地形专家划分或路由模块。critic 的简化单独比较成本与收敛结果，不影响参考配置。
只有出现可复现的技能冲突，并排除数据、课程和奖励问题后，才重新讨论 MoE actor。

### 感知与自然度的研究边界

- TAGA 提供主动选择局部地形信息的思路。官方 AME-2 已发布 TAGA 风格的 gaze
  选项，可用于实现核对；不把该选项等同于完整 TAGA 复现。先比较固定裁剪再评估
  学习式裁剪，并计入全局特征、critic 和地图构建的成本。
- Hiking in the Wild 的动作先验、几何边缘与足部体积约束、目标引导指令可以分别
  借鉴，不要求同时引入其 MoE 或深度视觉管线。
- AMP 从行走、转向和台阶相关动作开始。接入前检查数据许可、关节映射、坐标系、
  时间采样及覆盖范围。动作参考服务于适应地形，不能让模仿奖励压过任务目标。
- 稀疏石块上的边缘惩罚需要考虑实际可用支撑面积。平坦目标也需检查间距和高差，
  不能只凭局部平坦就判定可达。

## 训练期间的准备与资源衔接

第二阶段使用 `research/ame2-foundation` 分支和独立 checkout、虚拟环境、日志目录。
从第一阶段训练提交开始，第一阶段后续经过验证的修复再按需同步。
不改动运行中的第一阶段源码、HEAD、依赖和启动脚本。

GPU 不可用时先完成：源码差异表、模块实现、配置与 CLI 接线、CPU 前向/梯度检查、
保存恢复检查，以及明确的 GPU 冒烟命令。复用现有检查，只为迁移的具体风险补充验证。
不把“代码已写好”记录为“允许正式训练”。

GPU 衔接顺序：

1. GPU1 上允许在已有训练继续运行时进行小规模搭建测试。每次按 UUID 检查显存
   余量，从少量环境开始并保留充足余量；不停止或调整其他项目任务。整卡容量测试
   和正式训练只在实际空闲的 GPU 上进行，单次低利用率不算空闲。
2. GPU1 持续占用时，等待 GPU0 完成第一阶段的 base、finetune 及必要的结果验收。
   base 完成或阶段间进程短暂退出不代表第一阶段完成。
3. 第二阶段在 GPU1 先执行小规模环境 step/reset、真实 PPO 更新、checkpoint 恢复检查，
   再进行容量与吞吐测试；不得直接继承第一阶段的 4096 环境配置。
4. 短训练与容量测试通过、配置和训练预算明确后，才自动衔接第二阶段基线训练。
   任一检查失败即停止该任务并记录原因，不降级成另一套算法继续长训练。
5. 若 GPU1 已启动第二阶段任务，不在 GPU0 上重复启动同一实验。

GPU0 预计 2026-10-18 完成是资源规划假设，不是启动定时器。目标是在释放前准备好
可运行的验证链路；实际启动以第一阶段状态、第二阶段检查和实时资源为准。
共享机器上的空闲检测不能替代调度器资源预留，不通过空转占卡维持资源。

## 实验与代码维护

保留少量能够回答明确问题的对照，避免排列全部开关。固定一组地形种子、命令范围
和回放路线，包含平地到楼梯、连续地面到踏脚石等连接段。记录通过情况、停滞与
跌倒、典型视频、小时级训练耗时、峰值显存和吞吐。自然度结合动作回放与滑步、
抖动等现象判断，不只看 AMP 得分。候选改进形成结论前，再对有价值的结果复测。

使用同一套训练入口和必要的共享组件，以配置区分参考与改进。多头价值训练涉及
奖励、storage、returns 与 loss，必须一起验证，不整体复制一份 RSL-RL 作为捷径。
移植代码保留来源与许可；只增加有实际调用者的接口，不建设预想中的通用框架。

第二阶段使用独立 PR，不扩大当前 mjlab 升级 PR 的算法范围。默认算法变更需要独立
说明及效果依据；未经验证的研究配置不会自动成为默认。路线图发生实质变化时，
在同一变更中记录原因、证据和影响，避免文档与实际研究方向分离。

## 暂不纳入

- 真机部署、机器人通信、安全控制及部署仓库建设；以后单独决定是否另建仓库。
- 依赖尚未发布 neural mapping 模型的完整 student 或真实感知闭环。
- 同时切换到原始深度图输入、重建感知管线。
- MoE actor、按地形分配专家及为专家切换建设调度框架。
- 统一跑步、跳跃、攀爬、全身接触与高难度 parkour。
- 多机器人适配、动态障碍、全局导航及广泛失败恢复能力。
- 严格的通用评测平台、大量重复测试、为兼容多个 mjlab 版本添加分支。
- 在本次升级中切换默认算法、重命名项目或发布新版本。
